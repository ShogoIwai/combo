# combo-notion-to-md — Notion ページを Markdown ファイルにする

1 タスク = 1 ゴール。ゴールが満たされなければ完了とせず、上限まで loop する。

---

## このタスクの概要

| 項目 | 内容 |
| ---- | ---- |
| **できること** | Notion の 1 ページを MCP で取得し、本文を Markdown ファイルとして書き出す。ファイル名は**対象ページの表題**から決める。 |
| **入力** | ① Notion リンク（`https://www.notion.so/...` の URL、または page ID）② 出力**ディレクトリ**（**省略可 — 既定は起動時 CWD 直下の `work/`**）。ファイル名は指定できない（表題から決定論的に決まる） |
| **type** | `one-shot` — 出力 `.md` は毎回 Notion から作り直す。既存 `.md` を入力にしない。 |
| **出力** | `<出力ディレクトリ>/<ページ表題>.md`（未指定なら `work/<ページ表題>.md`）。先頭行が `# <表題>`、次行が `<!-- source: URL -->`、以降が MCP 取得結果そのまま。**H1 と出所行はスクリプトが決定論的に付ける**。 |
| **goal** | ①**取得ゲート**: 要求した page ID と応答の page ID が一致し、表題は取得結果のメタデータから取り、本文が truncate・要約されていないと確認できている。②**変換ゲート**: 出力 `.md` のファイル名が `sanitize(表題)` と一致し、先頭行が `# <表題>`、H1 と出所行を除いた本文が **MCP 取得結果と全文一致**（要約・意訳・省略・補完をしていない）。 |
| **検証** | 取得ゲートは手順 3 の確認結果を報告に書く（MCP が完全性を確認する手段を持たない場合は「取得結果との一致」までとし、「ページ全体を取得できた」とは書かない）。変換ゲートは `scripts/write_page.py` が **exit 0** を返すこと（スクリプトは**書く前に**検証し、書いた後に読み戻して全文一致を確認する。exit 1=I/O・2=引数不正・3=内容検証 NG・4=既存ファイルあり〈上書きの可否はユーザーに確認し、了承後に `--force`〉）。 |
| **loop 上限** | 3 回 |

## 使いどころ

- Notion の設計メモ・議事録をリポジトリへ取り込んで grep/レビュー対象にする
- 下流の text-only スキル（`combo-md-to-pdf`、各種レビュー skill）へ渡す前段

## 前提（どの MCP を使うか）

Notion アクセスは**ハーネスごとに経路が違う**。この skill はスクリプトで
Notion を叩かない — 取得は必ず MCP 経由で行う。

| ハーネス | 使うツール |
| -------- | ---------- |
| Claude Code | claude.ai の Notion ブラウザコネクタ（`notion-fetch` / 検索は `notion-search`） |
| Codex | Codex 側の専用 Notion MCP（`notion` サーバの fetch 相当ツール） |

どちらも使えない場合は**着手せず `検証不能`** とし、不足物（Notion MCP 未登録・
認証切れ）と再開条件を報告する。Codex 側の認証切れは `combo-notion-mcp-recovery`
で復旧する。

## 手順

1. **概要表の goal・入力・出力・検証を、この実行中の唯一の完了判定として固定する。**
   実行中に goal を緩和しない。
2. **入力を確定する。**
   - リンクから page ID を取り出す（URL 末尾の 32 桁 hex、`-` 付きでも可）。
     ID が取れないリンクは、そのまま fetch に渡してよい。
   - 出力先：**指定が無ければ既定の `work/`**（起動時 CWD 直下。絶対パスに固定され、
     無ければ自動で作る）。指定はディレクトリのみ受け付ける（`--outdir`）。
     **明示されたディレクトリが無いときは作らずに報告する**（自動生成は既定の
     `work/` だけ）。ファイル名はどちらの場合も表題から決まる。
3. **MCP でページを取得し、取得ゲートを通す**（前提表のツール）。
   - **応答の page ID が、入力リンクから取り出した ID と一致する**こと。違う
     ページを掴んでいたら goal を満たせないので取得し直す。
   - **表題は取得結果のメタデータから取る**。本文の見出しから推測しない。
     表題が取れなければ fetch をやり直す（loop）。
   - **本文が truncate・要約されていないか確かめる**：末尾が文の途中で切れて
     いないか、`...` や「省略」を示すマーカーが無いか、ページ末尾の見出しまで
     到達しているか。切れていれば分割取得して連結する（連結も改変はしない）。
   - MCP が完全性を確認する手段を持たない場合は、**「取得結果と一致」までを
     主張し、「ページ全体を取得できた」とは報告に書かない**。
4. **取得結果をそのまま scratchpad の `body.md` へ保存する。**
   **自分で書き換えない — 要約・意訳・省略・体裁直しをしない。**
   H1 と出所行はスクリプトが付けるので、ここでは足さない
   （取得結果が既に `# <表題>` を持つ場合はスクリプトが重複を落とす）。
   子ページ・データベースは**リンクのまま残す**（再帰取得はしない）。ユーザーが
   子ページも要ると言った場合のみ、1 ページずつこの手順を繰り返す。
5. **書き出す。**

   ```bash
   S=<launch-root>/combo/skills/combo-notion-to-md/scripts/write_page.py
   # 既定（出力ディレクトリ指定なし）: 起動時 CWD 直下の work/ に書く
   "$S" --title "ページ表題" --source "<Notion URL>" --body-file body.md
   # 出力ディレクトリが指定された場合
   "$S" --title "ページ表題" --source "<Notion URL>" --outdir /path/to/outdir --body-file body.md
   # 既存ファイルがあると exit 4 で止まる。ユーザーが上書きを了承したときだけ
   "$S" ... --force
   # 元ページが本当に空だと確認できたときだけ
   "$S" ... --allow-empty-page
   ```

   中間の `body.md` は scratchpad に置き、成果物ディレクトリに残さない。
6. **検証する。** exit 0 であること。exit 3（内容検証 NG）のときは**何も書かれて
   いない**ので、取得からやり直す（loop、最大 3 回）。exit 2 は引数、exit 1 は I/O。
   **exit 4 は出力先に既存ファイルがある合図**（この時点でも何も書いていない）。
   stderr の `ALERT:`（パス・サイズ・更新日時）を**そのままユーザーに提示して
   上書きしてよいか尋ね**、了承が得られたときだけ `--force` を付けて再実行する。
   勝手に `--force` を付けない。
7. **報告する。** 出力パス・表題・バイト数・取得元 URL、stderr に出た
   `NOTE:`（ファイル名の変換）と `WARNING:`（`--force` での上書き）をそのまま伝える。
   goal 未達なら `検証不能` として理由と再開条件を書く。

## 落とし穴

- **ファイル名は指定できない**：表題から決定論的に決まる（`sanitize(表題)` + `.md`）。
  別名で置きたいという要求は、この skill の契約変更なのでユーザーに確認してから。
- **表題の変換**：`/ \ : * ? " < > |` と制御文字は `_` に置換、NFC 正規化、末尾の
  空白/ピリオド除去、`.`/`..`/Windows 予約名（`CON` 等）は先頭 `_` へ退避、
  255 byte 超は UTF-8 安全に切り詰め。日本語・語中の空白はそのまま。
  変換したときは `NOTE:` が出るので報告に含める。
- **同名衝突**：切り詰め・置換で別ページが同じ名前になりうる。**既定では上書き
  せず exit 4 で止まる**ので、`ALERT:` をユーザーに見せて判断を仰ぎ、了承された
  ときだけ `--force` で上書きする。
- **取得の欠落**：fetch が長いページを要約・truncate して返すことがある。末尾が
  途切れていないか、見出しがページ末尾まで続いているかを手順 3 で確かめる。

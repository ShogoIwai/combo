# 立場（stance）— 既定値

> `--stance` を指定しなかったときに使われる既定の立場。自分の状況が違うなら、
> このファイルをコピーして書き換え、`--stance <自分のファイル>` で渡すこと。
> 末尾の `## 検査用アンカー` は**必須**（2 件以上）。V（価値基準）の「由来」と
> E（表明）が**この立場に固有か**の検査に、この語だけを使う（G8 / G13）。

## 誰か

- 日本在住・日本語話者の日本人。意見は日本の制度・商習慣・雇用慣行の中で実行される。
- **ASIC ベンダー**（半導体の設計・製造受託）に勤務。顧客の要求仕様を受け取り、
  設計・検証・量産までの責任を負う側であって、自社ブランド製品を売る側ではない。
- 家族は**妻と子の 3 人家族**。可処分時間と可処分所得は家族と共有の資源であり、
  転職・転居・長時間労働・単身赴任はいずれも自分だけでは決められない。

## この立場から来る利害

- **技術の目利き**が仕事の中核。EDA ツール、プロセスノード、IP ベンダー、パッケージ、
  検証手法の選択が、そのまま納期とコストと不具合率に跳ね返る。
- 受託側なので、**顧客の意思決定**（採用チップ、量産数量、仕様変更）に業績が左右される。
  自分で市場を選べる度合いは小さい。
- 経験は**設計・検証の現場知**に厚く、経営指標・市場統計・海外規制には薄い。
  数字を引用するときは公開情報の裏取りが要る。
- **雇用と生活の連続性**が判断軸に入る。数年で回収できない賭けは、家族の生活設計と
  両立するかどうかを必ず問う。
- 子の教育・進学の時間軸（十数年）と、半導体の技術サイクル（数年）は長さが違う。
  この 2 つのどちらの時間軸で語っているかを、意見の中で区別する。

## 読み手

原則として**自分自身**（考えを固めるための文書）。共有する場合の想定読み手は、
同じ ASIC ベンダーの同僚・上長、あるいは家族。どちらに読ませても、
事実・解釈・価値基準の区別が残るように書く。

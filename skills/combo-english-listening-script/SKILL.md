# combo-english-listening-script — テーマ → 日本語状況・日本語会話・英語会話を 1 本にまとめた md

One task = one goal. The goal is verified before the task is reported as
complete; if it is not met, the task loops until it is met or the loop limit is
reached.

---

## Task Summary

| Item | Content |
| ---- | ------- |
| **What it does** | 渡されたテーマに沿った場面（状況）を 1 つ決め、その場面の日本語会話（約1000文字）を書き、会話だけを自然な口語英語に訳して、3 要素を 1 つの md にまとめて保存する。 |
| **Input** | 次のどちらか（両方でもよい）。**テーマ**（skill の引数、または起動時のユーザー発言）／**素材**＝ `combo-opinion-five` の出力（意見 md `opinion_<slug>_<yymmdd>.md`、またはその run ディレクトリ `opinion_<slug>_<yymmdd>/`）。素材だけ渡されたときのテーマは意見 md の表題のお題。出力先 `--work` は任意で、既定は CWD 直下の `work/`。 |
| **type** | `one-shot` — 1 回の起動で 1 セット。既存の出力ファイルは上書きしない（同日・同じ見出しなら `_2`, `_3` … を付けて新規作成）。 |
| **Output** | `work/english_<slug>_<yymmdd>.md`（`work/` 直下の 1 ファイル。サブディレクトリは作らない）。中身はテーマ＋`## 状況`（日本語）・`## 会話`（日本語会話）・`## Conversation`（英語会話）の 3 セクション。 |
| **goal** | 出力ファイルが存在し、`scripts/check_script.py` の 8 ゲート（素材ありは G9 を足して 9 ゲート）が全 PASS すること。 |
| **Verification** | `python3 $S/scripts/check_script.py --file <出力md> --theme "<テーマ>" [--source <意見md>]` が exit 0（exit 2 は入力不備: ファイル・セクション欠落・素材 md が無い）。 |
| **loop limit** | 3（同じゲートで 2 回続けて FAIL したらその時点で打ち切り、`blocked` として報告する） |

`$S` はこの skill のディレクトリ（`combo/skills/combo-english-listening-script`）。

## When to Use

- 英語のリスニング・音読（シャドーイング、オーバーラッピング）用に、日本語と英語の対訳スクリプトがほしい
- 同じテーマで場面を変えたスクリプトを何本も作りたい（起動するたびに新しい md を 1 本ずつ作る）
- `combo-opinion-five` でまとめた自分の意見を、英語で話す練習の題材にしたい

使わない場面: 既存の英文の添削、単語帳づくり、TOEIC 等の試験問題形式の作成。

## Prerequisites

1. **python3**（検査スクリプト用。追加パッケージは不要）
2. **テーマ**か**素材**（意見 md）のどちらかが渡されていること。どちらも無ければテーマだけを短く尋ねて待つ（ファイルは作らない）。
   素材の run ディレクトリが渡されたら、その中のディレクトリ名と同名の md を素材とする（`work/` 配下の中間ファイルは読まない）。

## Procedure

1. **Fix the goal.** Task Summary の goal / Verification をこの run の唯一の完了条件として固定する。
   **素材があるときは、続けて素材を読む。** 下の「素材（combo-opinion-five の意見 md）の使い方」に従って素材を読み、
   会話に使う材料を拾う。テーマが渡されていなければ、意見 md の 1 行目 `# <お題>についての意見（…）` の
   `<お題>` をテーマにする。
2. **Decide the output file.** 出力は `<work>/english_<slug>_<yymmdd>.md`（`<work>` が無ければ作る。その下にサブディレクトリは作らない）。`yymmdd` は当日、`slug` は
   手順 3 で決める**場面を表す見出し**を短い英小文字＋ハイフンで書いたもの（2〜4 語。テーマの
   英訳そのものにはしない。例: テーマ「空港」で乗り継ぎ便に遅れる場面 → `english_missed-connection_260928`、
   テーマ「仕事」で提案書の締め切りを上司に相談する場面 → `english_proposal-deadline_260928`）。
   場面を先に決めてからファイル名を付ける（例: `work/english_proposal-deadline_260928.md`）。既に存在すれば
   末尾に `_2`, `_3` … を付けて新しく作る（例: `work/english_missed-connection_260928_2.md`）。既存のファイルは上書きしない。
3. **Write `english_<slug>_<yymmdd>.md`（3 要素をまとめた 1 ファイル）.** 次の構成で書く。見出しは表記どおり固定
   （検査スクリプトが `## 状況` / `## 会話` / `## Conversation` でセクションを切り出す）。
   ```
   # テーマ: <テーマ（ユーザーの入力そのまま。素材だけのときは意見 md のお題）>
   素材: <意見 md のパス>        ← 素材があるときだけ。無ければこの行ごと書かない

   ## 状況
   <誰と誰が、どこで、何をしている場面か。2〜4文>

   ## 会話

   <発言1>

   <発言2>

   ...

   ## Conversation

   <Utterance 1>

   <Utterance 2>

   ...
   ```
   **状況（`## 状況`）**
   - 会話の中で誰が話しているかを読み手が判断できるよう、登場人物の立場・関係はここで示す。
   - 素材があるときも、状況は素材の書き写しではなく**会話が起きる場面**として書く（誰と、どこで、何のきっかけで
     その話題になったか）。

   **日本語の会話（`## 会話`）**
   - **約1000文字**（空白・改行を除いて 900〜1100 文字）、6 発言以上。
   - **1 発言 = 1 段落**（発言ごとに空行で区切る）。発言を鉤括弧で囲まない。
   - **発言者名・話者ラベル・ト書き・括弧の補足を一切付けない**（`A:`、`店員：`、`【客】`、
     `（笑いながら）` などはすべて禁止）。誰の発言かは状況と会話の流れだけで分かるように、
     呼びかけ・質問と返答・相づちを入れる。

   **英語の会話（`## Conversation`）**
   - `## 会話` の**会話だけ**を訳す（状況は訳さない）。前置き・解説・語注は付けない。
   - **日本語と同じ順序・同じ区切り**で、1 発言ずつ対応させる（日英を突き合わせて音読するため）。
   - 直訳調を避け、ネイティブが実際に話す自然な口語英語にする。話者ラベル・ト書きは付けない。
4. **Verify.**
   ```bash
   python3 $S/scripts/check_script.py --file <出力md> --theme "<テーマ>"
   #   素材があるとき: --source <意見 md> を足す（G9 が増える）
   ```
   FAIL があれば該当セクションを直して再実行する（loop limit まで）。
5. **Report.** 下の Reporting に従う。

## 素材（combo-opinion-five の意見 md）の使い方

意見 md は**素材**であって、台本ではない。論点と手触りを借りて、場面と会話は自由に組み直してよい。
意見 md の章立て（`combo-opinion-five/reference/opinion_template.md`）のうち、拾うのは主に次の 4 つ。

| 意見 md の章 | 会話での使い道（目安） |
| ------------ | ---------------------- |
| §4 E 表明（意見・私はこうする） | 話し手の一人が持っている考え。会話の芯にする |
| §1 F 事実 | 会話の中で具体的に触れる話題・数字。1〜3 個に絞る |
| §2 I 解釈の「他の見方」／付録B 反論 | もう一人が返す疑問や反対意見。ここがあると会話が一方的な演説にならない |
| §3 V 価値基準（由来・トレードオフ） | なぜそう考えるのか、個人的な事情として一言にじませる程度 |

- **場面は自由に作る。** 立場ファイル（日本人・ASIC ベンダー勤務・妻と子の 3 人家族）から自然に起きる場面
  （同僚とのランチ、配偶者との夕食、海外の取引先との雑談 など）を選ぶとよいが、必須ではない。全部の論点を
  入れる必要はなく、約 1000 文字に収まる分だけ使う。
- **事実はねじ曲げない。** 数値・時期・主体を口にするなら §1 の記述に揃える。付録A（UNVERIFIED）の事柄は
  断定せず「〜らしいけど、確かめてない」のような言い方に留めるか、使わない。
- **意見 md の記法を持ち込まない。** `[C12]` のような台帳 ID、`F/I/V/E`、章番号、「事実:」「他の見方:」
  といった見出し語は会話に出さない（G9）。会話は普通の話し言葉にする。
- 素材の文を長くそのまま引き写さない。話し言葉に言い直す。

## Gates（`check_script.py`）

| Gate | 内容 |
| ---- | ---- |
| G1 theme | 冒頭の `# テーマ:` 行にテーマがそのまま書かれている |
| G2 situation | `## 状況` が空でなく日本語で書かれている |
| G3 ja length | `## 会話` が空白・改行を除いて 900〜1100 文字 |
| G4 ja turns | `## 会話` が 6 発言以上 |
| G5 ja no labels | `## 会話` に話者ラベル（`名前：` `【名前】`）や括弧のト書きが無い |
| G6 en no labels | `## Conversation` に話者ラベル（`Name:` `[Name]`）や `( )` `[ ]` `*…*` のト書きが無い |
| G7 en is English | `## Conversation` に日本語の文字が混ざっていない |
| G8 ja/en aligned | 日本語と英語の発言数が一致している |
| G9 source（`--source` 時のみ） | 素材 md が実在し、冒頭（`## 状況` より前）の `素材:` 行にそのファイル名があり、`## 会話` / `## Conversation` に台帳 ID（`[C12]`・`C12` 等）が無い |

### 決定的に検査できないこと

- 英訳が日本語の内容と意味の上で正しく対応しているか、英語が自然か（G8 は数しか見ない）。
- 話者ラベルなしでも誰の発言か文脈で分かるか。
- （素材があるとき）会話で触れた事実が素材の §1 と食い違っていないか、付録A の未確認事項を断定していないか。

これらは書き終えたあとに自分で読み直して確認し、Report で「確認した」と明記する。

## その後（任意）

- 英文法に関する追加の質問を受けたら、出力ファイルの `## Conversation` の英文を例に取りながら日本語で答える。
  質問への回答はファイルに書かない。
- 同じテーマで別のスクリプトを求められたら、Procedure を最初からやり直して別ファイルに作る。

## Output Contract

- 出力は `<work>/english_<slug>_<yymmdd>.md` の 1 ファイルだけ。サブディレクトリや中間ファイルは作らない（`ja_situation.md` などに分割しない）。
- 既存のファイルは上書きしない。
- 会話本文はチャットにも貼らない（ファイルを正本にする）。

## Reporting

完了時に次を報告する。

- 出力ファイルのパス
- 状況の要約（1 行）
- （素材があるとき）素材のパスと、会話に使った論点（§4 の意見と、相手役が返した反論・他の見方）を 1〜2 行で
- `check_script.py` の最終行（PASS/FAIL とゲート数）と、日本語会話の文字数・発言数
- 「決定的に検査できないこと」を読み直して確認したこと

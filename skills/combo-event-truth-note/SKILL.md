# combo-event-truth-note — イベントメモ → 裏取り＋深掘り → エッセンス → 自分のための md

One task = one goal. The goal is verified before the task is reported as
complete; if it is not met, the task loops until it is met or the loop limit is
reached.

---

## 下敷きにした本と、このスキルでのアレンジ

土門蘭『ほんとうのことを書く練習 ——「わたしの言葉」で他者とつながる文章術』
（ダイヤモンド社, ISBN 978-4-478-12386-7）。序章「私たちはなぜ『ほんとうのこと』が
書けないのか」＋第1章「『ほんとうのこと』を読む」／第2章「誰にも読ませない文章」を書く／
第3章「『ほんとうのこと』を書く練習」／第4章 書く手段（日記・短歌・エッセイ・インタビュー）／
第5章 書いたものが読まれるとき、という構成。

**本から採ったエッセンス（このスキル作者による要約。逐語引用でもページ指定でもない）**

- **ほんとうのこと ≠ 客観的事実**。「何が起きたか」は材料にすぎない。
- **ほんとうのこと ≠ 赤裸々な暴露／垂れ流し（排泄）**。強い言葉を吐くことではない。
- **ほんとうのこと = 自分がいま何を感じ、何を考え、何を求めているか**を、借り物でない
  自分の言葉で捉えたもの。
- そのためにまず **「誰にも読ませない文章」** を書く。他者の目線を締め出して初めて、
  体裁のための言葉が落ちる。→ このノートの読者は**自分ひとりに固定**する（G18）。
- 手段は日記（常時稼働のインフラ）／短歌（言語化のスナップショット）。
  作るのは**日記の側**、短歌は核を言い切れないときの受け皿として残す。

**このスキルで足したアレンジ（原典には無い）**

1. **ファクトチェック** — 本は「事実か否か」を問わないが、記憶は歪む。メモの事実主張を
   公開情報で裏取りし、**CORRECTED（メモと公開情報が食い違った箇所）** を明示する。
   **`CORRECTED` は食い違いがあったときだけ**使う（G8 が `corrected_to` とメモの実質的な
   差分を要求するため、単なる補足を `CORRECTED` に入れると差分を作文する圧力になる）。
   **食い違いではない補足**（正式名称が分かった・背景が埋まった）は `CONFIRMED` /
   `PARTIAL` の `status_rationale` に書くか、深掘り `D#` に回すこと。
   自分にとって最も価値が高いのは、この「その場では分からなかったことが埋まった」差分。
   **メモは記憶の素描であって答案ではない。** その場でいちいち書き取れないから後で調べる
   のであって、裏取りは採点ではなく**空白を埋める作業**である。表記ゆれ・呼び名・
   うろ覚えの数字を「誤り」として数え上げない（→「書かないこと」）。
2. **深掘り調査** — その場で分からず流したこと（用語・数字・前提）を、
   **「なぜ私がそれを知りたいのか」を一人称で書いてから**調べる。調べもの自体が
   何に引っかかっているかの証拠になる。
3. **前向きに閉じる** — エッセンスには **`keep`（次も続けたいこと）** を必ず持たせ（G15）、
   §9 には **`次にやること`** を置く（G16）。自責の語は §9 とエッセンスの地の文から
   締め出す（G21）。ノートの目的は自分を採点することではなく、**次に効く形で残すこと**。
4. **純粋なエッセンス抽出** — 全部を等価に残さず **3〜5 件**へ絞り、
   **何を落としたか（`cut`）を記録**する。落とした記録が無い要約は、絞ったのではなく
   単に書かなかっただけ。
5. **肉付け** — 絞ったエッセンスに、裏取り済み事実と深掘りを**根拠として**接ぐ
   （120 字以上）。感想を長くするのではなく、**裏の取れたものに繋ぎ直す**のが肉付け。

したがってこのノートは**共有物ではない**。読み手に配る組織向けの示唆が要る場合は
`combo-conference-report` の領分。

### 書かないこと（このノートを説教にしないための線引き）

このスキルは自分を点検する道具に見えやすいが、**点検の対象は外界の前提であって
自分の態度ではない**。次はいずれも書かない。

- **メモの書き方・記憶違い・呼び名のずれを落ち度として扱わない。** 「西口と呼んでいたが
  公式名は違った」は事実の更新であって、私の不注意ではない。`CORRECTED` は
  **「調べたら分かったこと」**として書く。
- **利用者としての感想・評価を、事実で否認しない。** 「順路が分かりにくい」「北側が古い」は
  実際に歩いた人の正当な体験であり、公式資料が別のことを言っていても取り下げない。
  事実行は感想の反証ではなく、**感想の隣に置く材料**である。
- **「自分は分かっていなかった」型の総括をしない。** 気づきは行動か問いの形で書く。
  ただし**自責の感情そのものは検閲しない**。悔しい・情けないと本当に感じたなら
  それは `感情`（§2）や `思考`（§3）に一人称で書いてよい。G21 が弾くのは
  **結語（エッセンスの `statement` と §9 の核の一文）を自己採点で閉じること**だけで、
  感情の中身ではなく**ノートの閉じ方**を見ている。
- **調べてきた数値を核に据えない。** 深掘りで拾った計画値・予算・年数は材料であって主題ではない。
  §9 の核の一文と `statement` は、**自分が歩いて感じたこと**を骨格にする。数値を本文で使うときは
  **出典の段階と年次を必ず添える**（素案か確定版か、いつ時点か、一次資料か二次記事か）。
  一次資料が読めず二次記事しか無い数値は `PARTIAL` 相当として扱い、断定に使わない。
- **知らなかったこと・調べなかったことを数え上げない。** 未確認は §5 と `UNVERIFIED` に
  静かに置くだけでよい。

**感想を外部の事実で「正当化」しない。** 「回りにくいと感じた」は体験として自足しており、
工事や計画はその**隣に置く材料**であって原因の証明ではない。`statement` を
「私の思い違いではなく〜だからだ」の形（体験 vs 事実の二者択一）で書かない。
`grounds` が示す範囲を超えた因果・全称は書かないこと（例: 一区画の通行止め告知から
「北側全体が順番待ちだ」とは言えない）。

不満や批判が出てきたら、**それを消さずに「では何があれば解決するのか」へ回す**。
深掘り（手順 6）はそのための場所で、**1 件は必ず「次に効く情報」**（今後の整備計画・
開催予定・入手方法・比較対象）に充てること。

### ファクトチェックと「他者の目線を締め出す」ことの緊張

本は「他者の目線を締め出す」ことから始めよと言うのに、このスキルは公開情報・出典・
ゲートという**第三者の目線**を持ち込んでいる。これは実在する矛盾なので、扱いを決めておく。

**事実監査は「ほんとうのことを決める工程」ではない。自分が反応した外的前提を点検する
補助工程である。** したがって順序と原則を固定する。

1. まず他者もゲートも意識せず、感情・思考・欲求を書く（手順 4）。
2. 次に、**外界についての記憶だけ**を監査する（手順 5）。感情は監査対象ではない。
3. **訂正された事実で感情を訂正しない。**「事実は違ったが、私はそう感じた」は両立する。
   `CORRECTED` になっても `感情/欲求` 行の `own_words` を書き換えないこと。
4. 最後に内面へ戻り、事実監査が自分の言葉を上書きしていないか確認する（手順 8）。

**副作用の警告**: 裏取りを課すと「検証可能な題材ばかり選ぶ」圧力が生まれる。
裏の取れない感情こそこのノートの本体なので、**事実行が少ないノートは失敗ではない**。
`UNVERIFIED` が多いことも、`思考`/`欲求` が大半を占めることも正常。

### プライバシー（私的ノートだからこそ）

このスキルは**メモの内容を外部の検索・取得経路に送る**。私的ノートでは外向きレポート
以上に重要なので、着手前に必ず守ること。

- **検索クエリに固有情報を載せない。** 顧客名・取引先名・未公開の製品名・個人名・
  社内の数値は、一般名詞や種別（「ある取引先」「国内の半導体ベンダ」）に置き換えてから
  調べる。裏取りできない固有情報は `PRIVATE_PRIMARY` か `UNVERIFIED` に倒す。
  **裏を取るために機密を漏らすのは本末転倒**（それをするくらいなら `UNVERIFIED` が正しい）。
- 面談・評価・体調・人間関係の記述は、そもそも監査対象にしない（`感情`/`思考` に置く）。
- `work/` にはメモ原文・感情・身体感覚・`PRIVATE_PRIMARY` の引用が**永続保存**される。
  出力先は**同期フォルダ・共有ドライブ・git 管理下を避ける**。git 配下に置くなら
  `.gitignore` を先に用意する。
- `PRIVATE_PRIMARY` の `quote` は判断に要る最小限にとどめる（資料本文の書き写しにしない）。
- 完成した md は**添付・貼り付け事故の対象**。共有するなら書き終えたあとに別途判断し、
  そのときは `combo-conference-report` で作り直す。

## Task Summary

| Item | Content |
| ---- | ------- |
| **What it does** | メモを単位に切り出し、1 件ずつ「事実 / 感情 / 思考 / 欲求 / 借り物」を裁定。事実は公開情報でファクトチェックし（CONFIRMED / CORRECTED / PARTIAL / UNVERIFIED / PRIVATE_PRIMARY）、メモの外を深掘り調査し、3〜5 件のエッセンスへ絞って肉付けし（各件に「次も続けたいこと」を持たせる）、核の一文・自分への問い・次にやることを立てる。 |
| **Input** | イベントメモ（txt/md）1 つ以上。イベント名は任意。**立場ファイルも読み手も要らない**（読み手は自分）。 |
| **type** | `one-shot`（ノート本文）＋ `incremental`（`work/ledger.json`・`digs.json`・`essence.json`・`evidence*` は残す） |
| **Output** | 単一の `.md`（既定 `<event>_truth_note_<yymmdd>.md`）と `work/`（`units.json` / `ledger.json` / `digs.json` / `essence.json` / `manifest.json` / `evidence.json` / `evidence/*.txt` / `summary.md` / `section*.md`）。 |
| **goal** | 出力 md が存在し、`scripts/check_note.py check` の 21 ゲートが全 PASS すること。 |
| **Verification** | `python3 scripts/check_note.py check --note <out.md> --work <work> --memos <memo...>` が exit 0（exit 2 は入力不備）。 |
| **loop limit** | 3（= **台帳・ノートを直して再検証した回数**。HTTP の retry とは別物） |

## When to Use

- イベント／会議／面談のメモが、事実と感想と反省文で混ざったまま腐っている
- 書き出すと勝手に「大変勉強になりました」型の報告文になり、自分が何を思ったのか残らない
- **その場で聞いた数字や固有名を、記憶のまま自分の前提にしてしまうのが怖い**
- その場で分からず流した言葉があり、調べないままにしている
- 引っかかったのに、何に引っかかったのか自分でも言えていない

使わない場面: 他人に配る参加レポート（→ `combo-conference-report`）、議事録の整形、
複数議論の統合（→ `combo-transcripts-to-scqa`）。

## Prerequisites

1. **python3**
2. **メモが実在し可読**であること
3. **Web 検索の経路**（`WebSearch`/`WebFetch`、または `mcp__codex__web_rag`）
4. **URL への HTTP アクセス**（`fetch_sources.py` が実取得する）。PDF 出典を使うなら
   **pdftotext**（poppler-utils）

3〜4 が無い環境では goal を満たせない。着手せず `blocked` で報告する（`failed` ではない）。

## Procedure

1. **Fix the goal.** Task Summary の goal / Verification をこの run の唯一の完了条件として固定する。
2. **Check the inputs.** メモの実在・可読、Web 経路を確認する。欠けていれば `blocked`。
3. **Segment（決定的）.**
   ```bash
   python3 scripts/init_ledger.py <memo.md> [...] --work <work> --event "<イベント名>"
   ```
   - 引数順に `N1..Nn`、単位に `O1..On`。`work` に既存生成物があると**何も書かずに**止まる。
   - **`rows` の `id/doc/context/text` は書き換えてはいけない**（G0 が再分割して照合する。
     メモ自体を後から書き換えるのも検出される）。
4. **層を裁定（LLM）.** `work/ledger.json` の `rows` **全行**を埋める。行を消さない。
   - `layer`: `事実`（起きたこと・言われたこと）／`感情`（内側で動いたもの）／
     `思考`（頭を通った考え）／`欲求`（こうありたい・こうしてほしい）／
     `借り物`（実感でなく、報告文の定型句や既製の枠組みをなぞっただけの記述）
   - `layer_rationale`: **その行固有**の理由を 30 字以上（G6）。
   - `own_words`: 自分の言葉での言い直し。写経は G3 で落ちる。
     `感情/思考/欲求` は一人称（私・自分・僕…）で（G4）。主語を消した評論に逃げない。
   - `body_sense`（任意）: からだの感覚。感情の裏取りは外部ソースでなく身体感覚で行う。
   - `borrowed_phrase`: `layer=借り物` のとき必須。**なぞった原文**をそのまま入れる（G13）。
   - `unknown` / `unknown_note`: 言葉にならないものは `true`。**埋めない**（G12）。
   - `charge`（0-5）: 引っかかりの強さ。手順 7 の抽出材料。
5. **ファクトチェック（LLM＋決定的）.** `layer=事実` の**全行**を公開情報で裏取りする。
   一次ソース（公式発表・規格団体・論文・決算資料）を優先し、二次記事しか無ければ `PARTIAL`。
   - `status`:
     - `CONFIRMED` — 公開情報とメモが一致
     - `CORRECTED` — **メモと公開情報が食い違った**（数値・時期・主体・名称）。
       `corrected_to` に公開情報側の内容、`status_rationale` に差分（G8）。
       **自分の落ち度としてではなく、事実の更新として書く。**
       食い違いではない単なる補足には使わない（→ `CONFIRMED` / `PARTIAL` か `D#`）
     - `PARTIAL` — 一部だけ裏が取れた
     - `PRIVATE_PRIMARY` — 非公開の一次資料しか根拠が無い（配布資料・社外秘スライド）。
       `private_sources` に `document`/`page`/`classification`/`holder`/`quote`。公開 URL は付けない
     - `UNVERIFIED` — 公開情報が見つからない。**捏造で埋めない。**
       `searched` に `{"queries": [...], "domains": [...]}`（G9）
   - `sources`: `title`/`url`/`publisher`/`date`/`accessed`/`quote`（**そのページに実在する
     逐語引用**、10 字以上）。実際に開いた URL だけ。
   - 裏取りで自分の記憶が崩れても、`text` は書き換えない（記憶の歪みごと記録に残す）。
6. **深掘り（LLM）.** `work/digs.json` に `D1..` を追加する。**1 件以上必須**（G14）。
   **うち 1 件以上は「次に効く情報」**（今後の整備計画・再訪時に使える手順・比較対象）に
   充てる。不満で終わった論点があれば、まずそれを問いに変換して調べること。
   該当する件には `"purpose": "next_use"` を付けて自分で分かるようにする
   （**この欄はゲートで検査していない**。形だけ一般的な背景調査を置いて通せる穴は
   開いたままなので、通すためでなく自分のために使うこと）。
   ```json
   [{"id":"D1","question":"…?","why":"私は…（一人称で動機）","finding":"…",
     "sources":[{"title":"","url":"","publisher":"","date":"","accessed":"","quote":""}],
     "unresolved":""}]
   ```
   - その場で分からず流した用語・数字・前提を選ぶ。`why` は**なぜ自分がそれを知りたいのか**
     を一人称で（20 字以上）。**ここが埋まらないなら、それは自分の問いではない。**
     ゲートを通すためだけの調べものを 1 件でっち上げるより、`why` が書ける問いが
     1 つも無いことを認めて `blocked` で止めるほうが正しい（G14 は 1 件以上を要求するが、
     それは「問いがあるはずだ」という前提ではなく「問いがあるなら調べよ」という規則）。
   - `finding` は 40 字以上、行ごとに固有。分からなければ `unresolved` に残す。
7. **Fetch the sources（決定的）.**
   ```bash
   python3 scripts/fetch_sources.py --work <work>
   ```
   台帳と `digs.json` の URL を実取得し `work/evidence.json` / `work/evidence/*.txt` に証跡を残す。
   **status 200 でない出典・引用がページ本文に無い出典は G7 で落ちる。** robots・403・ペイウォール・
   JS 描画・画像 PDF のように**再試行で直らない**ものはループを消費させず、ただちに公式 PDF／
   静的ページへ差し替えるか、`PRIVATE_PRIMARY` / `UNVERIFIED` へ裁定し直す。
   証跡ファイルを手で書くのは goal 未達の隠蔽（G7 が `text_sha256` を照合する）。
8. **エッセンス抽出と肉付け（LLM）.** `work/essence.json` に `E1..` を **3〜5 件だけ**書く（G15）。
   ```json
   [{"id":"E1","statement":"私は…（一人称・20 字以上）","from":["O3","O6"],
     "grounds":["O1","D1"],"cut":"…を落とした（20 字以上）",
     "keep":"次も続けたいこと（20 字以上）","flesh":"…（120 字以上）"}]
   ```
   - `from`: 由来した台帳 ID。`charge` の高い行、`借り物` と裁定した行、`CORRECTED` の行が
     良い出発点（その場では分からなかったことが埋まった場所）。
   - `grounds`: **裏取り済みの事実（CONFIRMED/CORRECTED/PARTIAL）か深掘り `D#` を必ず 1 つ以上**。
     感情だけを根拠にしたエッセンスは通らない。
   - `cut`: **何を落として絞ったか**。ここが書けないなら、まだ抽出していない。
   - `keep`: **次も続けたいこと・やってよかったこと**（G15）。反省の対に必ず一つ置く。
     「〜しなかった」ではなく「〜した／〜する」と書く。
   - `flesh`: 肉付け本文。`grounds` が `statement` をどう支えるかを自分の言葉で書く。
     **`grounds` の各 ID を本文中に明示する**（例: `版元も判型も違っていた（O2）`）。
     これは意味の証明ではなく、どの根拠を指して書いたかを後から辿るための表記規則（G15）。
     文字数稼ぎの一般論は G5（定型句）と `flesh` 複製検査で落ちる。
9. **Generate（決定的）.**
   ```bash
   python3 scripts/check_note.py report --work <work>
   ```
   `summary.md` / `section1..8.md` / `section10.md` が出る。**件数はここでしか作らない。**
10. **Write the note.** `reference/note_template.md` の章立てで 1 本の md を書く。
    - §0 は `summary.md` の見出し以降を**逐語で**（G20）。宛先は「誰にも見せない」（G18）。
    - §1〜§6・§10 は生成された `section*.md` の箇条書きを**そのまま貼る**。
      **行単位で完全一致**が要求される（連結・並べ替え・手書き追加・取りこぼしは全て FAIL、G11）。
      箇条書き以外の地の文（「この日は考えとして残ったものが無かった」等）は足してよい。
    - §7 / §8 は生成されたブロックを**見出しごと逐語で**貼る（G14 / G15）。
    - §5 は `unknown` 全件（G12）。
    - §9 に `核の一文:`（一人称・30 字以上・**由来の `E#` を書く**）、`次の問い:` 2 つ以上、
      `次にやること:` 1 つ以上（10 字以上・具体的な行動）（G16）。自責の語は置かない（G21）。
      **まとめでも決意表明でもない**。言い切れないなら短歌の行に置く。
    - §10 は `section10.md`（実取得した URL だけ）（G17）。
    - 定型句は `own_words`・エッセンス・§9 の**地の文**に置かない（G5）。
      `私は「勉強になった」で片づけようとしていた` のように**鉤括弧で名指す**のは可。
11. **Verify.**
    ```bash
    python3 scripts/check_note.py check --note <out.md> --work <work> --memos <memo.md> [...]
    ```
    `--memos` を渡すと manifest のパス申告を信用せずその入力で再現照合する（推奨）。
12. **Loop.** FAIL が残るうちは 4〜11 を回す（上限 3 回）。**ゲートを緩める／行を消す／
    `unknown` をそれらしい言葉で埋める／エッセンスを水増しする**のは修正ではない。
    上限に達したら残 FAIL を明示して `failed`。ネットワーク等の外部要因は `blocked` と区別する。

## Gates（`check_note.py check`）

| Gate | 見るもの | 塞いでいる迂回 |
| ---- | -------- | -------------- |
| G0 | 分割の不変性（メモ→units→rows を再分割し `id/doc/context/text` と `units.json` を全照合、メモの sha256） | `text` を書きやすい記述にすり替える／メモを削って単位を減らす／裏取り結果に合わせて記憶を書き換える |
| G1 | 台帳網羅（1 単位 = 1 行、ID 重複なし） | 触りたくない単位を消して 0 件 PASS |
| G2 | 未裁定 0（層・理由・own_words、事実は status と理由 30 字、借り物は原文） | 空欄のまま「書けた」と称する／事実でない行に status を付けて裏取り済みに見せる |
| G3 | `own_words` がメモの写経でない（15 字以上） | 言い直さず原文コピーで「自分の言葉」を装う |
| G4 | 感情・思考・欲求が一人称 | 主語を消して評論に逃げる |
| G5 | 定型句を own_words・エッセンス・§9 の**地の文**に置かない（「」で借り物として名指すのは可） | 報告文の語彙で自分の感情を上書きする／肉付けを一般論で水増しする |
| G6 | 層の裁定理由が行ごとに固有・30 字以上 | 同じ一文を全行に複製する |
| G7 | 出典の実体（実取得 status=200・`final_url`/`fetched`/`sha256` の存在・証跡ファイル名一致・`text_sha256` 一致・**ページ内に実在する引用**） | URL の作文、架空パス、証跡テキストの手編集、取得記録の偽装、別 URL の証跡の流用 |
| G8 | `CORRECTED` の訂正がメモと**実質的に違う**（正規化類似度 0.9 以下）／訂正後の内容が `status_rationale` か `own_words` に現れる／`PRIVATE_PRIMARY` の資料証跡と公開 sources の排他 | 語尾だけ足した空の「訂正」／何が正しいのか書かない訂正／非公開資料を公開裏取り済みに見せる |
| G9 | `UNVERIFIED` の探索証跡（queries / domains が文字列配列） | 「見つからなかった」だけで探索範囲が無い |
| G10 | 章立て（11 章・**表題の完全一致**・重複なし・順序） | 章タイトルを差し替えて別物を書く／同じ章を二度書いて前半を捨てる |
| G11 | §1〜§6・§10 が生成された `section*.md` の箇条書きと**行単位で完全一致** | 1 行に複数件を連結する／並べ替える／手で書き足す／取りこぼす／status を伏せる |
| G12 | §5 に `unknown` **のみ**全件 | わからないものを黙って本文に混ぜる／それらしく埋めて消す |
| G13 | §6 に手短に済ませた原文が残っている | 定型で済ませた記述を無かったことにする |
| G14 | 深掘り 1 件以上・**ID 一意かつ D1..Dn の連番**・`question` が問いの形・`why` が一人称 20 字以上・`finding` 40 字以上かつ固有・§7 に**全ブロック逐語** | 調べずに済ませる／同じ ID を並べて件数を作る／動機を書かない／§7 に見出しだけ置いて中身を書かない |
| G15 | エッセンス 3〜5 件・**ID 一意かつ E1..En の連番**・`statement` 一人称・`from` が実在 ID・`grounds` に裏取り済み事実か深掘りを 1 つ以上・**`flesh` に各 grounds ID を明示**・`cut` 20 字以上・`keep` 20 字以上・`flesh` 120 字以上かつ固有・§8 に全ブロック逐語 | 全部を等価に並べて絞らない／同じ ID を複製して件数を作る／感想だけを根拠にする／根拠を挙げるだけで本文が触れない／落としたものを書かず「絞った」と称する |
| G16 | §9 の `- 核の一文:` が**ちょうど 1 行**・一人称 30 字以上・**同じ行に実在する E#**／`- 次の問い:` が別内容で 2 件以上／`- 次にやること:` が 10 字以上で 1 件以上 | 核と無関係な行に E# を置いて紐づいたことにする／問いを立てず結論で閉じる／同じ問いを 2 回書く／気づきだけ書いて次の行動を書かない |
| G17 | §10 の URL が**裏取りに使った実取得済み URL**と一致 | 使った出典を隠す／未取得の URL を並べて厚く見せる |
| G18 | §0 が「誰にも見せない」宛先を宣言 | 途中から共有用レポートに化ける |
| G19 | placeholder・山括弧ゼロ | 雛形を残したまま完了扱い |
| G20 | §0 は `summary.md` の逐語（件数を手で書かない） | 件数を手集計して内訳を合わせる |
| G21 | 自責の語（反省・べきだった・恥ずかし・怠・浅はか等）をエッセンス・§9 の**地の文**に置かない | 気づきを反省文にすり替える／自分を採点して締める |

> 検査対象の本文からは**コードフェンスと HTML コメントを除去**してから見る。
> 「本文には嘘を書き、コードブロックの中に検査用の正解を置く」経路を塞ぐため。
> JSON の型不正・壊れた JSON は FAIL ではなく **exit 2（入力不備）** で止まる。

### 決定的に検査できないこと（正直な限界）

**「その言葉がほんとうに自分のものか」は機械では判定できない。** G4/G5 が落とせるのは
*形の上の*逃げ（主語の消去、既知の定型句）だけで、一人称で書かれた真面目そうな一文が
実は他人の言葉だった場合は素通りする。G12 も `unknown` フラグの扱いを見るだけで、
「わからないのに埋めた」かどうかは分からない。

**構造は検査できるが、意味は検査できない。** 強化したゲート（G11/G14/G15/G16）が
保証するのは *項目単位の対応と一意性* であって、次はいずれも未検査:

- 選んだ 3〜5 件がほんとうに核心か（G15 が見るのは件数・根拠 ID・`cut` の実在）
- `grounds` が `statement` を**意味として**支えているか（`flesh` への ID 明示は
  「どれを指したか」の表記であって、支持関係の証明ではない）
- 引用が主張を裏づけているか（G7 が見るのは引用がページに実在することまで）
- 核の一文が決意表明でなく引っかかりの一文か（G16 は行の形と E# の同居しか見ない）
- `事実` にすべき記述を `思考`/`借り物` に逃がしていないか（**この逃げ道は開いている**。
  私的ノートでは強制的な事実化より「今回は検証しない」と決められることを優先した）

共有物ではないので、`combo-conference-report` のような別モデルによる反証レビューは
課していない。**人に配るなら、そちらへ渡すこと。**

`work/` を書ける主体はメモも証跡も全部作り直して整合させる一貫改竄が原理的に可能で、
署名なしには防げない。**このスキルはゲートを通すために書くと必ず失敗する種類の作業を扱う。**
ゲートは足場であって、真偽の証明ではない。

## Output Contract

- ノートは**単一 md**、宛先は自分ひとり。`work/`（証跡込み）は残す（消さない）。
- 事実（§1）・感情（§2）・思考（§3）・欲求（§4）・わからないこと（§5）は**必ず別の節**。
- §1 の各行は status で確度が分かり、§10 → `evidence.json` で実取得記録まで辿れること。
- 手短に済ませた言葉は消さず §6 に原文で残す。「何を書き足せたか」が次に効く記録で、
  落ち度の一覧ではない。
- 言葉にならなかったことは**欠点ではない**。§5 に残すのが正しい出力で、埋めるのは誤り。
- 裏が取れなかったことも欠点ではない。`UNVERIFIED` として残す。
- 共有するかどうかは書き終えたあとの別判断。**このノートをそのまま人に配らない。**

## Reporting

完了時に次を報告する。

- 出力 md のパス、`work/` のパス
- `check_note.py check` の最終行（PASS/FAIL とゲート名）
- **`CORRECTED` になった事実**（メモと公開情報が食い違った箇所）— 必ず明示する。
  **落ち度としてではなく事実の更新として書く。** 序列をつけて「一番の収穫」に仕立てない
- §8 のエッセンス（`statement` のみ）と、`cut` で落としたもの
- §9 の核の一文、立てた問い、**次にやること**
- 各エッセンスの `keep`（次も続けたいこと）
- `借り物` に裁定した記述と、そこに書き足した自分の言葉
- `UNVERIFIED` / `unknown` として残したもの（塞がなかったもの）と、次のフォロー先
